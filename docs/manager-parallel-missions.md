# Manager: งานอ่านอย่างเดียวพร้อมกันสูงสุด 3 Agent

Manager แจก Task ย่อยที่เป็นงานข้อความหรืออ่านอย่างเดียวให้ Agent ต่างเจ้าของทำพร้อมกันได้สูงสุด 3 งาน งานทั้งหมดต้องผูกกับ Mission แม่ที่ Backend สร้างและบันทึกรายการงานย่อยครบแล้ว ไม่ใช้ข้อความใน Prompt เป็นสิทธิ์ข้าม Guard

## ขอบเขตและ Guard

- Backend เลือกเฉพาะงาน `codex_cli_task` ที่ผ่านการตรวจสิทธิ์เดิมและมีเจตนาอ่านอย่างเดียวหรือทำงานข้อความชัดเจน แล้วบังคับ `--read-only-work` ที่ Runner
- กลุ่มงานถือสิทธิ์ของ general semaphore เดิมร่วมกันจนงานสุดท้ายจบ งานทั่วไป งานแก้ไฟล์ งานใช้ Terminal และงานที่ต้องอนุมัติยังใช้เส้นทางเดิมทีละงาน กลุ่ม Council แยกตามข้อกำหนดเดิม
- แต่ละ Task ยังมี Mission ID, Owner, Authorization digest, Quota, Rate, Budget, Timeout, Audit และ Report ของตนเอง Agent เจ้าของเดียวกันไม่ทำหลายงานในกลุ่มพร้อมกัน
- การหยุด Worker ต้องยกเลิก Process ที่ติดตามทุก Mission และรอ Worker ทุกตัวจบ การหมดเวลาไม่ทำให้งานที่ถูกปิดกลับมาสำเร็จจากผลล่าช้า
- Manager สรุปสำเร็จหลังงานย่อยและรายงานครบจริงเท่านั้น การเขียนรายงานไม่สำเร็จต้องไม่กลายเป็นสรุปรวมพร้อมใช้

## ทดสอบจากหน้า HQ

1. เปิด Manager Agent แล้วส่งงานข้อความ 3 ข้อให้ Risk Guard, VPS Watch และ Mission Archivist พร้อมระบุชัดเจนว่า `ใช้โหมด read-only` ใช้เฉพาะข้อมูลในโจทย์ ไม่มีการเปลี่ยนระบบ
2. กดกระจายงานเข้าคิว เปิดโต๊ะ Mission แล้วค้นหารหัสทดสอบที่ใส่ในโจทย์
3. เปิดงานย่อยแต่ละใบ ตรวจ Owner, สถานะ, เวลาเริ่ม–จบ และ Report จริง แยกงานที่ยังรอคิวออกจากงานที่เริ่มรันแล้ว
4. ยืนยันการรันพร้อมกันจาก Process ของ Runner ที่ยังทำงานอยู่ครบสาม Mission ในเวลาเดียวกัน พร้อมตรวจ Audit การเริ่มและผลสำเร็จของแต่ละงาน ค่า `startedAt` ของ Mission เริ่มนับตั้งแต่รับงาน และ Health นับงานที่ Worker ถืออยู่ จึงใช้สองค่านี้ติดตามคิวได้ แต่ยังไม่เพียงพอที่จะพิสูจน์ว่า Process ทั้งสามรันซ้อนกันจริง
5. เปิด Mission แม่ ตรวจว่าครบ 3/3 แล้วกด **เปิดรายงานสรุปรวม** เพื่ออ่านผลย่อของเจ้าของทั้งสามจาก final executive summary ส่วนผลฉบับเต็มอยู่ใน Task ของแต่ละ Agent ไม่ใช้รายงานแผนเริ่มต้นเป็นหลักฐานว่างานเสร็จ

ตรวจ Health ด้วย `GET /api/health`: `missionWorker.activeMissionIds` และ `activeCount` แสดงงานที่ Worker กำลังถืออยู่ ส่วน `managerReadOnlyActiveCount` และ `managerReadOnlyWorkersAlive` แสดงสถานะกลุ่มงานขนาน ค่า `currentMissionId` ยังมีไว้รองรับผู้ใช้ข้อมูลรุ่นเดิม
