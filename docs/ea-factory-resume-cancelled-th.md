# ทำงานต่อจาก Build เดิมหลังยกเลิก

เส้นทางนี้ใช้กับงานโรงงาน EA ที่หยุดก่อนเริ่มการทำงานผ่าน MetaEditor หรือ Strategy Tester และมีหลักฐานพอให้ Backend ยืนยันการทำต่อได้

## การใช้งาน

1. เปิดโรงงาน EA และเลือก Build เดิม
2. เปิดหน้าสถานะงาน แล้วรอให้ระบบตรวจสถานะล่าสุด
3. เมื่อ Backend ยืนยันว่าทำต่อได้ จะมีปุ่ม **ทำงานต่อจาก Build เดิม**
4. กดครั้งเดียว แล้วติดตาม Mission และขั้นปัจจุบัน ระบบไม่สร้าง Build ใหม่

การเปิดหน้าเว็บ การโหลดสถานะ หรือการกดเลือก Build ไม่เริ่มงานที่ยกเลิกแล้วเอง ต้องมีคำสั่งทำต่อจากผู้ใช้

## งานเดิมถูกเก็บอย่างไร

- รอบที่ยกเลิกถูกเก็บเป็นประวัติ พร้อมข้อมูลยืนยันความสัมพันธ์กับรอบที่ทำต่อ
- ระบบใช้ Build, Strategy Spec, Source Version และหลักฐานที่ตรวจผ่านเดิม
- ถ้า Mission เดิมยังอยู่ในคิวหรือกำลังทำงาน ระบบติดตาม Mission นั้น ไม่ส่งงานซ้ำ
- ถ้าขั้นสร้าง Source ถูกยกเลิกและหยุดจริงแล้ว ระบบจะอนุญาตความพยายามใหม่ได้เฉพาะเมื่อพิสูจน์การหยุดได้ ไม่มี Source ที่ต้องเขียนทับ และยังมีจำนวนครั้งที่อนุญาตเหลืออยู่
- จำนวน Retry ไม่ถูกรีเซ็ตเมื่อกดทำต่อ ประวัติ Mission ที่หยุดไปแล้วไม่ถูกลบ
- การส่งคำขอเดิมซ้ำหลังเครือข่ายหมดเวลาใช้รหัสคำขอเดิม เพื่อคืนผลเดิม ไม่สร้างรอบควบคุมหรือ Mission เพิ่มซ้ำ

## กรณีที่ระบบยังต้องหยุด

ปุ่มทำต่อไม่ได้ปลด Guard ระบบยังปฏิเสธเมื่อการยกเลิกยังไม่จบ กระบวนการเดิมยังหยุดไม่แน่นอน มีงานอื่นที่ขัดกัน Terminal ที่ล็อกไว้เปลี่ยนไป หลักฐานถูกเปลี่ยน หรือใช้จำนวน Retry ครบแล้ว

กรณีเคยเริ่ม Compile/Backtest หรือมีการทำงานผ่านหน้าต่างที่ยังยืนยันผลไม่ได้ ไม่อยู่ในเส้นทางทำต่อนี้ เพราะการสั่งซ้ำอาจสร้างผลซ้อน ต้องตรวจหลักฐานและใช้เส้นทางกู้เฉพาะขั้นที่รองรับ

Build ที่มีประวัติทำต่อแบบนี้ยังไม่รองรับการสั่ง **เริ่มเฉพาะ Backtest ใหม่** ระบบจะปฏิเสธก่อนแก้ข้อมูล เพื่อไม่ให้ประวัติการทำต่อสองรูปแบบปะปนกัน การทำขั้น Compile และ Backtest ตามลำดับปกติยังใช้การตรวจเดิม

Quota, Approval, Budget, Timeout, Kill switch, ลำดับขั้น และการตรวจ Source/Report ยังคงทำงาน ถ้าโควตาหมดและไม่มีสิทธิ์ใช้เครดิตที่ยืนยันครบ Mission จะรอโดยไม่เริ่มโมเดล และยังถือว่า EA ไม่สำเร็จจนกว่าทุกขั้นจะมีหลักฐานผ่านจริง

## ใช้เครดิตคงเหลือกับ Build ที่อนุญาต

เจ้าของเครื่องสามารถอนุญาตเฉพาะ Build เดิมผ่าน `POST /api/automation/existing-credit-policy` ด้วย `{ "buildId": "ea-build-...", "allowed": true }` ค่าเริ่มต้นคือไม่มี Build ใดได้รับอนุญาต เปลี่ยน `allowed` เป็น `false` เพื่อถอนสิทธิ์ และตรวจรายการได้จาก `GET` ที่เส้นทางเดียวกัน

สิทธิ์ผูกกับตัวตนและข้อกำหนดกลยุทธ์ของ Build มีอายุสูงสุด 24 ชั่วโมง การส่งคำขอเดิมซ้ำไม่ต่ออายุ ไม่สร้าง Mission และไม่เริ่มงานที่ยกเลิกไว้ ต้องสั่งทำต่อแยกต่างหาก ระบบจึงรับช่วง Mission เดิมเมื่อรอบควบคุมทำงาน

ก่อนเริ่ม AI และก่อนการแก้โค้ดรอบย่อย ระบบตรวจข้อมูลเครดิตล่าสุดจาก Codex และตรวจสิทธิ์อีกครั้ง เครดิตต้องเหลือจริง ผู้ให้บริการต้องไม่ติดข้อจำกัดการใช้จ่าย และ Guard อื่นต้องผ่าน งานที่ไม่เกี่ยวข้องยังใช้เงื่อนไขโควตาเดิม การอนุญาตนี้ไม่รองรับการซื้อเครดิตหรือเปิดเติมเครดิตอัตโนมัติ

หน้าสถานะจะแสดงข้อความอนุญาตใช้เครดิตเฉพาะ Build เมื่อข้อมูล Backend ปัจจุบันยืนยันเท่านั้น เมื่อเสร็จงานสามารถถอนสิทธิ์ได้โดยไม่กระทบ Source หรือผล Compile/Backtest

## ขอบเขตการตรวจสอบ

ต้องทดสอบคำขอซ้ำและพร้อมกัน ข้อมูลหน้าจอเก่า การกดยกเลิกจากรอบเก่า การเริ่ม Coordinator ไม่สำเร็จ การเปลี่ยน Terminal หลักฐานไม่ตรง การรับช่วง Mission เดิม และการเริ่ม Source ใหม่หลังพิสูจน์ว่าหยุดจริงแล้ว พร้อมตรวจว่า Build และ Mission ที่ไม่เกี่ยวข้องไม่ถูกแก้ไข

ผล automated tests ของเส้นทางทำต่อไม่ใช้แทนผล Compile หรือ Visual Backtest ของ EA จริง และไม่ใช่การ Release
