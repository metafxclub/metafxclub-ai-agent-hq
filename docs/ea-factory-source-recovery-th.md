# กู้คืน Source ใน Build เดิม

เส้นทางนี้ใช้รับ Source ที่ผู้พัฒนาแก้ไขแล้วกลับเข้า Build ที่ขั้นสร้างโค้ดล้มเหลว โดยยังผูกกับ Strategy Spec เดิม ไม่ใช่การเริ่มสร้าง EA ใหม่ และไม่เรียก AI ให้สร้างโค้ดซ้ำ

## สิ่งที่ต้องคงอยู่

- Build และข้อกำหนดกลยุทธ์เดิม
- Mission และรายงานล้มเหลวเดิม พร้อมเวลาและสาเหตุจริง
- จำนวน Retry และประวัติ Retry เดิม
- หลักฐานการทำงานเดิมทุกชิ้น รวมถึงประวัติรอบที่ยกเลิกหรือไม่สำเร็จ

Source ที่รับใหม่ต้องมีหลักฐานที่มาว่าเป็นการกู้คืนโดยผู้พัฒนา พร้อม digest ของโค้ดและ Strategy Spec, ใบรับคำขอ และประวัติการกู้คืน ห้ามเปลี่ยน Mission เดิมให้ดูเหมือน AI สร้างโค้ดสำเร็จ

Backend สร้าง Mission บันทึกการรับ Source แยกหนึ่งรายการที่ใช้รหัสแน่นอน ไม่เรียกโมเดลหรือรันโปรแกรม และไม่ใช่การสร้างโค้ดซ้ำ การส่งคำขอเดิมซ้ำต้องได้ Mission และ Version เดิมกลับมา

## วิธีใช้

เลือก Build เดิมในหน้า **2 สถานะการทำงาน** เมื่อ Backend ยืนยันว่ากู้คืนได้ จะมีช่องเลือกไฟล์ Source เลือก `.mq5` หรือ `.mq4` ให้ตรงแพลตฟอร์ม ขนาดไม่เกิน 48 KB ใช้ชื่อไฟล์ภาษาอังกฤษ ตัวเลข ขีดกลาง หรือขีดล่าง แล้วกด **ตรวจและรับ Source เข้า Build เดิม**

รับการกู้คืนสำเร็จได้หนึ่งครั้งต่อ Build หากไฟล์ไม่ผ่านตรวจจะยังไม่รับเป็น Source Version หลังรับแล้วให้ตรวจสถานะสดและทำต่อจาก Build เดิมตามปุ่มที่ Backend อนุญาต การกู้คืนเองไม่เริ่ม Worker หรือเปิด Terminal

สำหรับเครื่องมือผู้พัฒนา ใช้ `POST /api/props/right_server_racks/ea-factory/builds/:buildId/recover-source` พร้อมฟิลด์ `idempotencyKey`, `strategySpecDigest`, `failedMissionId`, `failureReportId`, `fileName`, `content` เท่านั้น รับค่าผูก Build จาก `sourceRecovery` ใน Read Model ปัจจุบัน ห้ามส่ง path ในเครื่องหรือผลผ่านที่คำนวณจากหน้าบ้าน

## การตรวจและทำต่อ

Backend ตรวจสถานะ Build ปัจจุบันและความตรงกันของข้อกำหนดก่อนรับโค้ด ตรวจ Source ด้วยด่านเดิม และสร้าง Version ที่ตรวจย้อนหลังได้ จากนั้นยังต้องผ่าน Source Review, Compile และ Visual Backtest ตามลำดับ การรับ Source สำเร็จจึงยังไม่ใช่หลักฐานว่า EA สร้างเสร็จแล้ว

คำขอซ้ำที่มีรหัสและเนื้อหาเดิมต้องคืนใบรับคำขอเดิม ไม่สร้าง Version หรือส่งงานซ้ำ หากใช้รหัสเดิมกับโค้ดคนละชุด หรือเปลี่ยน Build/Spec/Mission ต้องปฏิเสธ

หากคำขอรอนานหรือการเชื่อมต่อขาด ให้เก็บรหัสคำขอเดิมและตรวจสถานะก่อน ห้ามสร้างรหัสใหม่เพื่อเลี่ยงคำขอที่ยังไม่ทราบผล

การอ่านสถานะครั้งแรกหลังข้อมูลเปลี่ยนอาจต้องตรวจหลักฐานหลาย Build เมื่อยังตรวจไม่เสร็จภายใน 2 วินาที Backend ตอบ HTTP 202 พร้อม `kind: ea_factory_refresh_deferred`, `status: deferred`, `readinessConfirmed: false` โดยไม่มี Read Model หรือสิทธิ์เริ่มงาน หน้าจอเก็บข้อมูลเดิมเพื่อแสดงผล ทำเครื่องหมายว่ายังไม่สด และปิดคำสั่งจนกว่าจะได้รับสถานะที่ตรวจแล้ว การตรวจเบื้องหลังใช้ร่วมกันได้เพียงหนึ่งชุด จึงไม่สร้างคิวตรวจซ้ำตามจำนวนคำขอหน้าจอ

การตอบ 202 ไม่ใช่การยืนยันว่า Build ผ่านหรือหยุด งานเดิมยังดำเนินต่อได้ตามสถานะ Backend และคำสั่งทำงานทุกคำสั่งยังต้องผ่านการตรวจสดเดิม การอ่านหน้าจอไม่เผยแพร่ผลตรวจเข้าแคชที่ใช้อนุญาตคำสั่ง

## เครดิตและการทดสอบ

การรับ Source ที่แก้ไขเองไม่ต้องใช้เครดิตโมเดล หากขั้น Review ต้องเรียก AI และโควตารวมเต็ม การใช้เครดิตเดิมต้องได้รับสิทธิ์เฉพาะ Build ผ่านนโยบายเครดิตตามเดิม และยังตรวจเครดิตสด การหมดอายุ การเพิกถอน และขีดจำกัดผู้ให้บริการก่อนเรียกงาน

การกู้คืนไม่ซื้อเครดิต ไม่เปิดเติมเงินอัตโนมัติ ไม่เปลี่ยนสิทธิ์เทรดจริง และไม่ Release ผล Backtest เป็นหลักฐานการทดสอบของ Source และค่าทดสอบชุดนั้นเท่านั้น ไม่ใช่การรับประกันผลกำไร
