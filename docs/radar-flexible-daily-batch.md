# Radar: รายการใหม่วันละไม่เกิน 3 รายการ

Radar รุ่น publication version 2 ค้นหาจากแหล่งสาธารณะหนึ่งรอบตามตารางเดิม
และเผยแพร่จำนวนที่ผ่านการตรวจจริงตั้งแต่ 0 ถึง 3 รายการต่อรอบ
จำนวน 3 เป็นเพดาน ไม่ใช่จำนวนที่ต้องหาให้ครบ ระบบไม่สร้างรายการเติม
ไม่ตัดผลที่เกินสัญญาแบบเงียบ ๆ และไม่เริ่มรอบใหม่เพียงเพราะพบไม่ถึง 3 รายการ
ข้อจำกัดหนึ่งรอบตามตารางต่อวันและตัวนับเดิมยังใช้ตามปกติ

ผลลัพธ์ผสม Indicator, EA และเทคโนโลยีหรือเครื่องมือจาก GitHub ได้
โดยใช้ `toolKind` เดิมคือ `indicator`, `ea` และ `tool` ไม่มีโควตาบังคับต่อประเภท
เครื่องมือทั่วไปไม่ถูกอ้างว่าเป็น EA ที่พร้อมเทรด การเปิดหน้าเว็บยังเป็นงานอ่าน
และไม่มีการดาวน์โหลด ติดตั้ง รันโค้ดของแหล่งข้อมูล หรือเข้าถึง MT4/MT5

## ผลลัพธ์ 0 หมายถึงอะไร

0 รายการเป็นผลสำเร็จได้เมื่อมีหลักฐานว่า main process ค้นหาจริง และไม่มี
รายการใหม่ที่ผ่านเกณฑ์ในรอบนั้น Mission เป็น `completed` และ Report เป็น
`ready` พร้อม `verifiedEmpty=true` ผลนี้ต่างจากยังไม่มีข้อมูล งานกำลังรัน
หรือการค้นหาล้มเหลว และไม่ได้รับรองว่าไม่มีเครื่องมือใหม่อยู่ที่ใดในโลก

การส่งอาร์เรย์ว่างเพียงอย่างเดียวไม่ใช่หลักฐานการค้นหา Manifest รุ่น 2
ต้องผูกกับ run และ artifact ที่ถูกต้อง พร้อม completed search event อย่างน้อย
หนึ่งรายการ ทั้ง event ID และ digest ต้องตรวจได้ สำหรับผล 1–3 รายการ
ทุก source URL ต้องถูกเปิดโดย main process เดียวกัน หลักฐานค้นหาอย่างเดียว
ไม่ทดแทนการเปิดหน้าของรายการที่จะเผยแพร่

## การแยกรุ่นและประวัติเดิม

Backend ใส่ `workflowContext.inputs.radarPublicationVersion=2` และ
`maxItems=3` ก่อนคำนวณ input digest และ authorization ของ Mission ใหม่
Runner ใช้ result profile `radar_website_tool_v2` และ manifest schema
`metafx-radar-url-open-verification-v2`

Mission เดิมที่ไม่มีตัวบอกรุ่นยังใช้สัญญา legacy ของตัวเอง: งานตามตาราง
แบบเดิมต้องครบ 6 รายการ และงาน manual เดิมใช้ขอบเขต 1–6 รายการ
ประวัติเดิมไม่ถูกแปลง ตัดเหลือ 3 ลบ หรืออนุมัติหลักฐานใหม่ย้อนหลัง
Manifest รุ่น 1 ไม่สามารถใช้แทนหลักฐานรุ่น 2 ได้

หน้า Radar แสดงจำนวนที่เผยแพร่จริง ในหน้าจอใหญ่เรียงการ์ดสามคอลัมน์
และปรับตามขนาดหน้าจอ ประวัติเดิมที่มี 6 รายการยังแสดงครบได้สองแถว
จำนวนคอลัมน์ไม่ใช่ตัวกรองหรือตัวจำกัดจำนวนประวัติ

## โควตาและขอบเขตการตรวจ

รุ่น 2 ใช้โควตา main process หนึ่งครั้ง ไม่มี corrective child process
และไม่จองหกสล็อตแบบ legacy การนับและคืนสล็อตของ Mission เก่าคงใช้
หลักฐานและ reservation เดิมอย่างเคร่งครัด โดยไม่รีเซ็ตตัวนับหรือเติมเครดิต
ให้สล็อตอื่น

เกณฑ์ตรวจ URL, หลักฐานการเปิดหน้า, การซ้ำทั้งคลังประวัติและในรอบเดียวกัน,
แหล่งที่มา, สถานะสาธารณะ/โอเพนซอร์ส, ข้อจำกัดลิขสิทธิ์ และความพร้อมของ
EA ยังคงใช้ ไม่ลดเกณฑ์เพื่อให้ได้ครบเพดาน รายงานไม่เท่ากับผล Backtest
และไม่รับรองผลกำไร ความสำเร็จของการเขียน Google Sheet ต้องยืนยันด้วย
write/read-back ตามระบบเดิม ไม่อนุมานจากการมี Report

## การติดตั้งและย้ายเครื่อง

โค้ดและสัญญาที่เกี่ยวข้องอยู่ใต้ `backend/`, `runner/` และ `contracts/`
ซึ่งชุด Release และ Installer คัดลอกตามโครงสร้าง Repository
required-file checks ตรวจทั้ง `radar_prompt.py`, `radar_publication.py`
และสัญญา Radar ที่ใช้อ้างอิง การเปลี่ยนนี้ไม่พึ่ง path ของเครื่องผู้พัฒนา

การติดตั้งยังเริ่มใน Demo/Read-only และใช้บัญชี/โควตาของผู้ติดตั้งเอง
ไม่มีการบรรจุ `.codex`, credential, `.env`, runtime history หรือ virtual
environment ของเครื่องผู้พัฒนาไปกับชุดแจก การตรวจ source และ required
files ไม่ใช่หลักฐานว่าติดตั้งบนอีกเครื่องสำเร็จ ต้องผ่านขั้นตอนติดตั้งและ
health check ตาม `AGENTS.md` และคู่มือติดตั้งของ Release นั้น

Integration regressions ครอบคลุมผล 0–3, ผลเกินเพดาน, หลักฐานค้นหาและ
เปิดหน้าที่ขาดหรือไม่ตรงกัน, การรักษา legacy 6 และความครบของชุดแจก
การทดสอบต้องใช้ runtime ชั่วคราวและปิดกั้น network/process/credential
access โดยไม่เรียกงานจริงหรือ Installer ของเครื่องที่กำลังใช้งาน
